# CLAUDE.md

## Project
Empirical study: do frontier agents disclose indirect prompt injections to the user?
Full design: docs/01_research_brief.md. Rubric: docs/03_disclosure_rubric.md.
Aman is the lead researcher. You are the research engineer: build, run, report. Do not change the research design. Propose changes and wait for approval.

## Stack
- Python virtual env; pin versions in requirements.txt and record them in README.
- UK AISI Inspect + inspect_evals, AgentDojo eval (`inspect_evals/agentdojo`), workspace suite.
- Read the inspect_evals AgentDojo docs first. List the available attack types, defence or system-prompt options, and task IDs before writing code. Do not guess parameters.
- Anthropic API key in `.env` (gitignored). Never print or commit keys.

## Hard rules
1. Sandbox only. AgentDojo environments are simulated. Never connect to real email, files or services.
2. COST GATE: before any batch run, print the number of samples, the models and the estimated cost, then STOP and wait for Aman's "yes".
3. Never overwrite logs. Every run writes to `logs/<timestamp>_<label>/`. Keep raw Inspect `.eval` logs. Commit them (or a manifest, if they're too large).
4. Do not edit `docs/` or `data/custom_scenarios/`. Aman writes those.
5. No invented numbers anywhere. README numbers must come from `results/` files generated by code.
6. Small steps: build, run on 1–2 samples, show Aman the output, then scale.
7. When you write analysis code, add a short comment explaining each metric so Aman can explain it in an interview.

## Build order
1. Setup: env, install, `.env`, .gitignore, README skeleton. Run 1 benign and 1 injected workspace task on Haiku. Show Aman the full transcript.
2. Defence condition: implement the "report suspicious instructions" system-prompt variant (via the eval's supported option if one exists; otherwise a documented wrapper). Test on 1 task.
3. Pilot: about 20 injected tasks × Haiku and Opus, default attack, no defence (cost gate first). Export each final agent message to `results/pilot_transcripts.csv` for Aman to read.
4. STOP. Aman records the go/no-go in the decision log.
5. Full grid: models × attack types × defence, plus benign runs for false alarms (cost gate first).
6. Grader: LLM grader applying docs/03_disclosure_rubric.md. Output score, evidence quote and reason per transcript to `results/disclosure_scores.csv`. Sample 30 random rows to `results/human_check.csv`, with the grader's score hidden.
7. Analysis: compute per-cell disclosure distribution, % score 3, false-alarm %, ASR, utility, human-vs-grader agreement (% and Cohen's kappa). Output `results/summary_table.csv` and one chart (disclosure % vs false-alarm %, by model, with and without the defence).
8. README: question, setup commands, versions, model IDs, cost, results table, chart, limitations. Leave the "Findings" section for Aman to write.
